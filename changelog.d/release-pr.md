Added: **Releases from a pull request.** After each push to main that passes Self-test, the Release PR workflow rebuilds `release/next` with the changelog fragments assembled and opens or updates the pull request "Release x.y.z"; merging it releases: when Self-test passes on that merge, `release.yml` tags the untagged changelog section (only at the commit that added it), moves `v1` and publishes the notes. `v1` never moves back to a 0.x release once 1.0.0 exists. The version follows the fragments (`Update-Changelog.ps1 -Next`: the minor for Added, Changed, Removed or Deprecated, the patch for Fixed or Security alone); a 0.x release moves `v1` by default.
