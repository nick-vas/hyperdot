Changed: `plan -Do sync` mirrors the plan to a GitHub Project instead of a board on another service. `plan -Do sync -Board @me` (or a login) makes a private project titled "<game> plan" with a Column field (Backlog, Design, To Do, Doing, Testing, Done), links it to the game's GitHub repository and puts every task on it; later syncs create, move, import and archive items both ways. It uses the GitHub CLI signed in with the `project` scope, so the kit stores no key. `-Board` takes `<owner>/<number>`, a project URL or an owner, `-Card` became `-Item` (a `PVTI_` id), task JSON has `itemId` instead of `cardId`, the board field is `projectBoard`, and `plan.json` has a `project` block (`owner`, `number`, `columns`, `toArchive`). The error codes of the earlier sync are now `project-credentials`, `project-error` and `project-column-missing`, and the sync workflow needs a `HYPERDOT_PROJECT_TOKEN` secret. The `game`, `godot-game-plan` and `weekly-review` skills describe the new flow.
